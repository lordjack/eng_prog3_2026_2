Do DER ao modelo logico

A modelagem logica traduz o Diagrama Entidade-Relacionamento (DER) em estruturas que o SGBD entende.

DER (Conceitual)Logico (SGBD)
EntidadeTabela
Atributo simplesColuna
Atributo multivaloradoNova tabela + FK
Atributo compostoColunas separadas
IdentificadorChave primaria (PK)
Relacionamento 1:NFK no lado N
Relacionamento N:NTabela associativa
Relacionamento 1:1FK em uma das tabelas

Convencao Tabelas no plural, colunas no singular, snake_case: clientes, data_nascimento.

Chaves e Constraints

Tipos de chave

  • PK: identifica cada linha. Unica, nao nula.
  • FK: referencia PK de outra tabela.
  • UK: valor unico, mas nao e identificador principal.
  • Composta: PK com 2+ colunas (ex: matriculas).

Constraints

  • NOT NULL — obrigatorio
  • DEFAULT — valor padrao
  • CHECK — validacao
  • ON DELETE CASCADE — exclui filhos
  • ON UPDATE CASCADE — atualiza FK
Cuidado com CASCADE
Em producao, CASCADE pode apagar dados sem aviso. Para dados sensiveis, prefira RESTRICT ou SET NULL.

Aula 2

Por que normalizar?

Organizar dados para reduzir redundancia e evitar anomalias.

Anomalia de insercao
Nao consigo inserir um dado sem inserir outros. Ex: cadastrar professor sem disciplina.
Anomalia de atualizacao
Atualizar o mesmo dado em varias linhas. Ex: mudar nome do departamento em 50 registros.
Anomalia de exclusao
Ao excluir um registro, perco dados de outra entidade. Ex: excluir unico aluno de um curso e perder os dados do curso.

Importante Normalizar demais pode prejudicar performance. Para a A2, foque na 3FN.

Resumo: 1FN -> 2FN -> 3FN

1FN
Atributos atomicos. Sem grupos repetitivos. "Cada celula tem um valor so."
2FN
Dependencia total da PK. "Nada depende de parte da chave."
3FN
Sem dependencias transitivas. "Nada depende de algo que nao e chave."
Mnemonica
1FN = Celula atomica | 2FN = PK inteira | 3FN = Sem transito (transitividade)

O que e DDL?

DDL (Data Definition Language) define e altera a estrutura do banco. Diferente do DML que manipula dados.

CategoriaComandosFuncao
DDLCREATE, ALTER, DROP, TRUNCATEEstrutura (schema)
DMLINSERT, UPDATE, DELETE, SELECTManipulacao de dados
DCLGRANT, REVOKEPermissoes
TCLCOMMIT, ROLLBACKTransacoes

Lembrete DDL e auto-commit no MySQL — nao da para desfazer com ROLLBACK.

Tipos de dados do MySQL

Numericos

  • INT — inteiros
  • BIGINT — inteiros grandes
  • DECIMAL(10,2) — dinheiro
  • TINYINT — booleano (0/1)

Data

  • DATE — YYYY-MM-DD
  • DATETIME — data + hora
  • TIMESTAMP — com timezone

Texto

  • CHAR(n) — fixo (CPF, CEP)
  • VARCHAR(n) — variavel (nomes)
  • TEXT — textos longos
  • JSON — dados JSON

Especiais

  • ENUM — lista fixa
  • SET — multiplos valores

Importante Para dinheiro, use DECIMAL. Nunca FLOAT ou DOUBLE (imprecisao).

CREATE TABLE com FK

Forma 1 — Inline

CREATE TABLE pedidos (
    id_pedido   INT AUTO_INCREMENT PRIMARY KEY,
    data_pedido DATE NOT NULL,
    id_cliente  INT NOT NULL,
    FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente)
        ON DELETE RESTRICT ON UPDATE CASCADE
);

Forma 2 — Constraint nomeada (recomendada)

CREATE TABLE pedidos (
    id_pedido   INT AUTO_INCREMENT PRIMARY KEY,
    data_pedido DATE NOT NULL,
    id_cliente  INT NOT NULL,
    CONSTRAINT fk_pedido_cliente
        FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente)
        ON DELETE CASCADE ON UPDATE CASCADE
);

DROP e TRUNCATE

DROP TABLE
Remove tabela, dados, indices e constraints. Irreversivel.
DROP TABLE IF EXISTS alunos;
TRUNCATE TABLE
Remove todos os dados, mantem estrutura. Mais rapido que DELETE.
TRUNCATE TABLE alunos;
DROP DATABASE IF EXISTS escola; -- Apaga TUDO!
Seguranca
Sempre use IF EXISTS. Nunca rode DROP sem backup. Em producao, prefira RENAME TABLE.

Criando o BD do projeto (A2)

Exemplo: Task Manager — sistema de tarefas para a API REST.

CREATE DATABASE IF NOT EXISTS taskmanager
    CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE taskmanager;

CREATE TABLE usuarios (
    id_usuario    INT AUTO_INCREMENT PRIMARY KEY,
    nome          VARCHAR(100) NOT NULL,
    email         VARCHAR(150) NOT NULL UNIQUE,
    senha_hash    VARCHAR(255) NOT NULL,
    ativo         TINYINT(1) DEFAULT 1,
    criado_em     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE tarefas (
    id_tarefa     INT AUTO_INCREMENT PRIMARY KEY,
    titulo        VARCHAR(200) NOT NULL,
    descricao     TEXT,
    status        ENUM('pendente','em_andamento','concluida') DEFAULT 'pendente',
    prioridade    ENUM('baixa','media','alta') DEFAULT 'media',
    id_usuario    INT NOT NULL,
    criado_em     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario)
        ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB;

Boas praticas

Nomenclatura
snake_case. Tabelas no plural. PK: id_tabela. FK: id_tabela_ref. Campos de auditoria: criado_em, atualizado_em.
Seguranca
Nunca senha em texto plano. Use password_hash() no PHP. Soft delete com ativo ou deletado_em. Documente com COMMENT.

Soft delete vs Hard delete

Soft delete (recomendado)
Marca como inativo. Permite recuperacao.
ativo TINYINT(1) DEFAULT 1
Hard delete
Apaga com DELETE. Risco de perda de dados e quebra de integridade.

Indices e performance

Indices aceleram consultas, mas ocupam espaco e deixam INSERTs mais lentos.

-- Indice simples
CREATE INDEX idx_tarefa_status ON tarefas(status);

-- Indice composto
CREATE INDEX idx_tarefa_user_status ON tarefas(id_usuario, status);

-- Indice unico
CREATE UNIQUE INDEX idx_email ON usuarios(email);

-- Ver indices
SHOW INDEX FROM tarefas;

-- Remover indice
DROP INDEX idx_tarefa_status ON tarefas;
Regra de ouro
Toda FK deve ter um indice! Sem indice, o MySQL faz full table scan em JOINs.

-- 1. Banco
CREATE DATABASE IF NOT EXISTS taskmanager
    CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE taskmanager;

-- 2. Usuarios
CREATE TABLE usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    senha_hash VARCHAR(255) NOT NULL,
    ativo TINYINT(1) DEFAULT 1,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- 3. Tarefas
CREATE TABLE tarefas (
    id_tarefa INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(200) NOT NULL,
    descricao TEXT,
    status ENUM('pendente','em_andamento','concluida') DEFAULT 'pendente',
    prioridade ENUM('baixa','media','alta') DEFAULT 'media',
    id_usuario INT NOT NULL,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario)
        ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB;

-- 4. Indices

CREATE INDEX idx_tarefa_user ON tarefas(id_usuario);
